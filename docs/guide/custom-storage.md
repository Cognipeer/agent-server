# Custom Storage

Implement your own persistence - or put an existing system behind the agent-server
API. There are two ways:

1. Extend `BaseStorageProvider` and implement the `_`-hooks (it adds the "is connected"
   check and id generation), or
2. implement the `StorageProvider` interface directly.

## The request context

Every data method takes the per-request `RequestContext` (see
[Request Context](./request-context.md)) as its **last, optional** argument. Use it
to scope data by tenant/user. Providers that don't need it can leave the parameter out.

```typescript
interface RequestContext {
  user?: { id: string; metadata?: Record<string, unknown> };
  data: Record<string, unknown>; // whatever resolveContext put there
}
```

## Using BaseStorageProvider

```typescript
import {
  BaseStorageProvider,
  type Conversation, type CreateConversationParams, type GetConversationsParams,
  type PaginatedResult, type RequestContext,
} from '@cognipeer/agent-server';

export class TenantStorage extends BaseStorageProvider {
  async connect() { /* open pool */ this._connected = true; }
  async disconnect() { this._connected = false; }

  // ids are generated by the base class
  protected async _createConversation(id: string, params: CreateConversationParams, ctx?: RequestContext): Promise<Conversation> {
    const tenantId = ctx?.data.tenantId as string;
    return db.conversations.insert({ id, tenantId, ...params });
  }

  protected async _getConversation(id: string, ctx?: RequestContext) {
    // never return another tenant's row, even if the id is known
    return db.conversations.findOne({ id, tenantId: ctx?.data.tenantId });
  }

  protected async _getConversations(params: GetConversationsParams, ctx?: RequestContext): Promise<PaginatedResult<Conversation>> {
    /* ... filter by tenant and params.userId ... */
  }

  // _updateConversation, _deleteConversation, _createMessage, _getMessages,
  // _getMessage, _deleteMessage, _saveFile, _getFile, _getFileContent,
  // _deleteFile, _createTask, _getTask, _getTasks, _updateTask, _deleteTask,
  // _createTaskResult, _getTaskResult
}
```

Hook signatures (all end with `ctx?: RequestContext`):

| Group | Hooks |
| --- | --- |
| Conversations | `_createConversation(id, params, ctx)`, `_getConversation(id, ctx)`, `_getConversations(params, ctx)`, `_updateConversation(id, params, ctx)`, `_deleteConversation(id, ctx)` |
| Messages | `_createMessage(id, params, ctx)`, `_getMessages(conversationId, params, ctx)`, `_getMessage(id, ctx)`, `_deleteMessage(id, ctx)` |
| Files | `_saveFile(id, params, ctx)`, `_getFile(id, ctx)`, `_getFileContent(id, ctx)`, `_deleteFile(id, ctx)` |
| Tasks | `_createTask(id, params, ctx)`, `_getTask(id, ctx)`, `_getTasks(params, ctx)`, `_updateTask(id, params, ctx)`, `_deleteTask(id, ctx)` |
| Task results | `_createTaskResult(id, params, ctx)`, `_getTaskResult(taskId, ctx)` |

## Implementing the interface directly

When the data already lives elsewhere (another service, an existing conversation
store) implement `StorageProvider` and map the calls:

```typescript
import type { StorageProvider } from '@cognipeer/agent-server';

class ExistingStoreAdapter implements StorageProvider {
  constructor(private readonly store: MyStore) {}
  async connect() {}
  async disconnect() {}
  isConnected() { return true; }

  async getConversation(id: string, ctx?: RequestContext) {
    const row = await this.store.find(ctx!.data.tenantId as string, id);
    return row ? toConversation(row) : null;
  }
  // ...
}
```

Notes for scoped stores:

- Returning `null` from `getConversation` yields a 404 - use that for "not yours"
  instead of leaking existence. (Ownership is additionally enforced by the server
  through `conversation.userId` when `resolveContext` is configured.)
- Files and tasks have no owner check in the server beyond `task.userId`; scope them
  by `ctx` too if clients must not reach each other's ids.
- `getMessages` is called with `params` possibly `undefined`.
- Methods must be safe to call concurrently; the server issues several per request.
